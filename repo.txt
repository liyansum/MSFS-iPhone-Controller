# MSFS iPhone 局域网飞行控制器完整方案

## 一、项目目标

开发一套由 **Windows PC 端 + iPhone App** 组成的 Microsoft Flight Simulator 2020 辅助控制系统。

iPhone 不显示电脑游戏画面，也不承担远程桌面功能，而是作为独立的无线飞行控制器使用。

整体目标：

```text
iPhone
│
├─ CoreMotion 姿态控制
│    ├─ 左右倾斜 → Aileron / Roll
│    └─ 前后倾斜 → Elevator / Pitch
│
├─ Throttle 油门
├─ Rudder 方向舵
├─ Elevator Trim 配平
├─ Flaps 襟翼
├─ Brake / Parking Brake
├─ Gear 等常用控制
│
└─ Map 地图
     ├─ 当前飞机位置
     ├─ 飞行航迹
     ├─ 当前航线
     ├─ 航点
     └─ 航点经纬度
            │
            │ Wi-Fi LAN
            ▼
Windows Companion
            │
        SimConnect
            │
            ▼
        MSFS 2020
```

第一版不使用 ViGEm、不模拟 Xbox 手柄。

Windows 程序直接通过 SimConnect 向 MSFS 发送飞控事件。MSFS 2020 官方提供 `AXIS_AILERONS_SET`、`AXIS_ELEVATOR_SET`、`AXIS_RUDDER_SET`、`AXIS_ELEV_TRIM_SET` 等标准飞控输入事件，因此没有必要再经过虚拟 Xbox 控制器这一层。

# 三、PC 与 iPhone 的连接方式

## 3.1 不做公网连接

使用场景已经确定：

```text
PC ───── 同一个路由器/AP ───── iPhone
```

因此删除公网设计中的：

```text
UPnP
PCP
公网IPv6
NAT穿透
端口映射
```

你提供的 `MSFS-SimGPStoAndroid` 已经实现了 SimConnect → UDP → 手机的数据结构，并且当前 PC 端默认从 SimConnect 获取飞机位置、航向、Pitch、Roll、地速、空速等信息。

我们的项目可以参考其 SimConnect 管理部分，但网络部分简化为纯局域网模式。

## 3.2 iPhone 设置页

首次启动：

```text
主机地址
192.168.1.100

控制端口
36666

服务端口
36667

[ 测试连接 ]

状态：
● PC 已连接
● MSFS 已连接
延迟 4 ms

[ 保存并进入控制器 ]
```

IP 自动保存。

以后启动 App：

```text
自动连接上一次主机
```

如果失败：

```text
PC 未连接
[重新连接]
[修改主机]
```

第一版不需要自动扫描局域网。

后续可以增加 Bonjour/mDNS 自动发现，但不作为首版依赖。

# 四、为什么使用 UDP + TCP 两条通道

## UDP 36666：实时控制

专门处理：

```text
Aileron
Elevator
Rudder
Throttle 拖动过程
实时控制状态
Ping/Pong
```

陀螺仪控制属于持续状态：

```text
旧数据丢失
      ↓
不应该等待重传
      ↓
直接使用更新的数据
```

所以 UDP 更适合。

---

## TCP 36667：可靠状态与命令

负责：

```text
建立会话
设备认证
连接状态

Flaps +
Flaps -
Trim
Gear
Parking Brake

飞机状态
航线
航点
设置
错误信息
```

例如：

```text
用户点击 FLAPS+
        ↓
TCP Command #138
        ↓
PC
        ↓
SimConnect
        ↓
MSFS
        ↓
实际襟翼状态
        ↓
PC
        ↓
iPhone
```

不会因为一个 UDP 包丢失导致用户明明按了襟翼却没有动作。

# 五、控制数据频率

建议：

```text
CoreMotion：

100 Hz 采样


iPhone → PC：

60 Hz 默认
100 Hz 高刷新模式


PC → MSFS：

每个模拟帧应用最新控制状态


MSFS → PC：

SIM_FRAME 获取


PC → iPhone Telemetry：

10～20 Hz


地图轨迹：

约 1 Hz / 按距离变化采样
```

你提供的项目已经使用 `SIMCONNECT_PERIOD_SIM_FRAME` 按模拟帧读取用户飞机信息。

因此我们的 Windows 程序可以继续采用：

```text
SimConnect thread
      ↓
SIM_FRAME
      ↓
读取最新 iPhone ControllerState
      ↓
写入飞控
      ↓
读取飞机状态
```

避免 UDP 网络线程直接操作 SimConnect。

# 六、iPhone 姿态控制

这是整个 App 的核心。

不要直接使用未经处理的原始 gyroscope rotation rate。

使用：

```text
CoreMotion
   ↓
CMDeviceMotion
   ↓
CMAttitude / Quaternion
```

Apple 的 `CMDeviceMotion` 提供经过系统融合的设备姿态信息，`CMAttitude` 可以得到 roll、pitch、yaw、rotation matrix 和 quaternion。

## 6.1 控制关系

本文统一术语：

```text
iPhone 左右倾斜
      ↓
Aileron
      ↓
飞机 Roll


iPhone 前后倾斜
      ↓
Elevator
      ↓
飞机 Pitch
```

真正的 Rudder / Yaw 单独由屏幕控制。

---

# 七、姿态零点设计

不能要求用户每次都把手机保持绝对水平。

点击：

```text
RECENTER
```

时记录：

```text
neutralAttitude = currentAttitude
```

之后控制依据：

```text
relativeAttitude
=
currentAttitude × inverse(neutralAttitude)
```

这样用户可以：

```text
坐着
躺着
手机微微倾斜
改变握持姿势
```

然后重新按一次 RECENTER。

当前姿态立即成为：

```text
Aileron  = 0
Elevator = 0
```

Core Motion 本身支持获得相对姿态变化，因此适合这种“当前姿势作为控制中心”的实现。

# 八、姿态映射

第一版默认参数：

```text
Roll 最大角度：
±30°

Pitch 最大角度：
±20°

Dead Zone：
2°

Expo：
1.4

Smoothing：
开启
```

例如 Roll：

```text
-30°                       +30°
 │                           │
-100%           0           +100%
 │             │              │
左满副翼       中立          右满副翼
```

Pitch：

```text
-20°          0          +20°
 │            │            │
-100%         0          +100%
```

实际输出：

```text
normalized = -1.0 ～ +1.0

↓

-16383 ～ +16384
```

MSFS 官方的 `AXIS_AILERONS_SET` 和 `AXIS_ELEVATOR_SET` 正是使用这一整数轴范围。

# 九、Deadzone + Expo

不要简单线性映射。

否则手机只动一点：

```text
2°
3°
4°
```

飞机都会跟着不停晃。

推荐曲线：

```text
2°以内
    ↓
0

超过Deadzone
    ↓
归一化
    ↓
Expo
    ↓
平滑
    ↓
MSFS
```

大致手感：

```text
手机角度        飞控输出

0°              0%
2°              0%
5°              5～10%
10°             20～30%
15°             40～50%
20°             65～75%
30°             100%
```

因此：

小动作适合巡航微调，

大动作仍然可以快速打满舵面。

设置页允许分别调整：

```text
Roll Sensitivity
Pitch Sensitivity

Roll Max Angle
Pitch Max Angle

Deadzone
Expo
Smoothing

Invert Roll
Invert Pitch
```

# 十一、切换到地图时自动 DISARM

这是非常重要的行为。

用户进入：

```text
地图 Tab
```

意味着手机很可能会被拿起来、转动或者调整位置。

因此：

```text
Control → Map

自动：

GYRO DISARM
Aileron → 0
Elevator → 0
Rudder → 0
```

回到：

```text
Map → Control
```

不自动重新 ARM。

需要用户：

```text
点击 ARM
```

重新校准之后才继续飞行。

这样不会因为查看地图导致飞机突然转弯。

# 十三、油门控制

左侧：

```text
THROTTLE

100%
 │
 █
 █
 █
 █
 █
 │
 0%
```

手指上下拖动。

输出：

```text
0.0 ～ 1.0
        ↓
0 ～ 16383
```

MSFS 2020 提供 `AXIS_THROTTLE_SET`，标准油门输入范围为 0～16383。

## 一个重要设计

**油门不能每秒 60 次永久覆盖。**

因为以后如果飞机存在：

```text
Autothrottle
自动油门
```

持续发送：

```text
THROTTLE 60%
THROTTLE 60%
THROTTLE 60%
...
```

会不断和飞机本身抢控制。

因此：

```text
用户正在拖油门
        ↓
持续发送 throttle

用户松手
        ↓
停止主动写入 throttle

MSFS
        ↓
返回真实 throttle 状态
        ↓
更新 iPhone UI
```

也就是说：

**触摸期间控制，松手以后由 MSFS 状态接管。**

# 十四、Trim 设计

Trim 不采用普通绝对 Slider。

建议右侧做：

```text
        ▲
        │
      NOSE UP
        │
      +1.8°
        │
      NOSE DN
        │
        ▼
```

使用类似实体 Trim Wheel 的操作方式。

向上滑：

```text
ELEV_TRIM_UP
```

向下滑：

```text
ELEV_TRIM_DN
```

发送增量命令。

然后：

```text
MSFS实际Trim
      ↓
PC读取
      ↓
iPhone
      ↓
显示 +1.8°
```

MSFS 也提供绝对 `AXIS_ELEV_TRIM_SET`，但首版使用增量控制更适合和自动驾驶等其他系统共同工作。标准 Elevator Trim 事件由 MSFS 飞控事件接口提供。

# 十五、Flaps

底部：

```text

```

不要使用：

```text

25%

75%
100%
```

这种固定档位。



主页底部：

```text

```

这是一个**自动回中的 Slider**。

拖动：

```text

↓
-16383

中间
↓
0

右
↓
+16383
```


# 十八、PC → iPhone 状态同步原则

所有控件均遵循：

```text
用户操作
   ↓
iPhone Command
   ↓
Windows
   ↓
SimConnect
   ↓
MSFS
   ↓
真实状态
   ↓
Windows
   ↓
iPhone UI
```

而不是：

```text
用户点击 FLAPS+
↓
iPhone 自己显示 FLAPS 10°
```

这样即使：

```text
MSFS拒绝命令
飞机系统改变状态
自动驾驶改变Trim
自动油门改变Throttle
```

iPhone 最终显示的仍然是模拟器真实状态。

# 十九、UDP 控制协议

不使用 JSON 发送陀螺仪。

使用固定 Binary Packet。

建议：

```text
ControlPacket
{
    magic        uint32
    version      uint8
    flags        uint8

    sequence     uint32
    timestamp    uint64

    sessionId    uint32
    axisMask     uint16

    aileron      int16
    elevator     int16
    rudder       int16

    throttle     uint16
}
```

`axisMask` 非常重要。

例如：

```text
AILERON   = bit 0
ELEVATOR  = bit 1
RUDDER    = bit 2
THROTTLE  = bit 3
```

假设：

```text
Gyro = ARMED
Throttle没有触摸
Rudder没有触摸
```

则只发送有效：

```text
Aileron
Elevator
```

PC 不会持续覆盖：

```text
Throttle
Rudder
```

---

# 二十、Sequence 与 Timestamp

UDP 每包包含：

```text
sequence
timestamp
```

例如：

```text
10231
10232
10234
10235
```

发现：

```text
10233
```

丢了。

不用管。

直接使用：

```text
10234
```

如果出现：

```text
10236
然后收到
10235
```

10235 直接丢弃。

绝不能把旧控制状态重新应用到飞机。

# 二十一、断线保护

这是第一版必须实现，不属于后期优化。

## 控制包超时

PC 如果：

```text
250 ms
```

没有收到新的实时控制包：

立即：

```text
GYRO DISARM

Aileron = 0
Elevator = 0
Rudder = 0
```

但是：

```text
Throttle
Trim
Flaps
Gear
```

**保持当前状态。**

绝不能断线后：

```text
Throttle → 0
```

否则飞行过程中 Wi-Fi 抖一下就会直接收油门。

# 二十三、TCP 会话

建立连接：

```text
iPhone
   ↓
HELLO
{
 protocolVersion
 appVersion
 deviceName
}
```

PC：

```text
WELCOME
{
 sessionId
 serverVersion
 simConnected
 aircraftName
}
```

之后 UDP Packet 必须携带：

```text
sessionId
```

PC 只处理当前有效会话的数据。

这样同一局域网其他机器随便向 36666 发 UDP 数据不会控制飞机。

# 二十八、计划航线

航线部分由 Windows 获取。

SimConnect 提供：

```text
FlightPlanActivated
```

系统事件。

当新的 Flight Plan 被激活时，SimConnect 会向客户端返回所激活 Flight Plan 的文件名。

所以 PC：

```text
FlightPlanActivated
        ↓
获取 .PLN 路径
        ↓
解析 PLN
        ↓
Waypoints[]
```

得到：

```text
Waypoint 0
ICAO
Latitude
Longitude
Altitude

Waypoint 1
...

Waypoint N
```

然后 TCP 一次性发送到手机。

# 三十五、线程模型

```text

├─ receive events

│
└─ latestControllerState

├─ commands

└─ watchdog
```

UDP 线程不要直接不停调用 SimConnect。

而是：

```text

↓
Atomic / Mutex
↓
LatestControllerState

↓
读取 LatestControllerState

发送到 MSFS
```

这样线程关系非常清楚。

# 三十九、异常处理

必须考虑：

```text
Wi-Fi 丢包
PC程序重启
MSFS重启
iPhone锁屏
iPhone App 被杀
PC切换网络
游戏暂停
航班重新载入
Flight Plan改变
```

原则：

```text
任何异常
↓
首先保证飞控不会卡在满舵状态
```

因此：

```text
实时控制失联
↓
中心化

持久状态
↓
保持
```

也就是：

```text
Aileron    → CENTER
Elevator   → CENTER
Rudder     → CENTER

Throttle   → HOLD
Trim       → HOLD
Flaps      → HOLD
Gear       → HOLD
```
